The Aily Blockly IDE employs a robust, multi-platform CI/CD pipeline built on GitHub Actions. It handles complex requirements including regional flavor builds (Global vs. CN), automated code signing via SignPath for Windows, notarization for macOS, and multi-region distribution using Cloudflare R2.

## Pipeline Architecture

The pipeline is triggered on pushes to the `deploy` and `beta` branches, or manually via `workflow_dispatch` [.github/workflows/main.yml:3-9](). It orchestrates four primary build jobs: `build-windows`, `build-windows-cn`, `build-macos`, and `build-macos-cn` [.github/workflows/main.yml:12-400]().

### Build Flavor Logic
The build system uses a \"flavor\" concept to differentiate between regional releases. This is managed by `scripts/build-electron.js`, which accepts a `--flavor` argument [.scripts/build-electron.js:5-7]().
*   **Global Flavor**: Uses `eu` as the region key, prefixing artifacts with `aily-blockly` [.scripts/build-electron.js:8-9]().
*   **CN Flavor**: Uses `cn` as the region key, prefixing artifacts with `aily-blockly-CN` [.scripts/build-electron.js:8-9]().

## Windows Build and SignPath Integration

Windows builds require Authenticode signing to avoid SmartScreen warnings. Aily Blockly uses **SignPath** for secure, cloud-based signing.

1.  **Build**: The runner executes `npm run build:global` or `build:cn`, which triggers `electron-builder` to package the app without signing [.github/workflows/main.yml:32-34]().
2.  **Artifact Upload**: The unsigned `.exe` is uploaded as a GitHub artifact [.github/workflows/main.yml:40-45]().
3.  **SignPath Request**: The `signpath/github-action-submit-signing-request` action sends the artifact to SignPath. The `signing-policy-slug` is dynamically determined: `test-signing` for beta branch and `release-signing` for deploy branch [.github/workflows/main.yml:47-55]().
4.  **Artifact Configuration**: SignPath follows rules in `.signpath/artifact-configuration.xml` to sign the main installer, the Electron executable, DLLs, and native `.node` modules [.signpath/artifact-configuration.xml:7-30]().
5.  **Hash Synchronization**: Since signing modifies the binary, the `latest.yml` file (used by the auto-updater) must be regenerated with the new SHA512 hash and file size [.github/workflows/main.yml:65-133]().

Sources: [.github/workflows/main.yml:40-135](), [.signpath/artifact-configuration.xml:1-32]()

## macOS Build and Notarization

macOS builds are performed on `macos-latest` runners. They involve code signing with Apple Developer certificates and notarization to satisfy Gatekeeper requirements.

### Entitlements and Security
The macOS build applies specific entitlements defined in `build/entitlements.mac.plist` to allow Electron's JIT compilation and the loading of unsigned native modules [.build/entitlements.mac.plist:1-25]().

## Distribution and Multi-Region Sync

The pipeline distributes artifacts to Cloudflare R2 buckets, which serve as the backend for the auto-update system.

| Region | Build Flavor | Update URL (from config.json) | Distribution Target |
| :--- | :--- | :--- | :--- |
| Global | `global` | `regions.eu.updater` | Cloudflare R2 (Global Bucket) |
| China | `cn` | `regions.cn.updater` | Cloudflare R2 (CN Bucket) |

Sources: [scripts/build-electron.js:7-12](), [.github/workflows/main.yml:500-550]()

### AI-Generated Changelogs
Upon successful deployment, the pipeline triggers a step to generate changelogs using AI. This process analyzes git commits between the current and previous release tags to produce user-friendly release notes that are then published to the update server.

## Build Script Implementation

The `scripts/build-electron.js` acts as the bridge between the environment variables and the build tools. It dynamically constructs `builderArgs` for `electron-builder` [.scripts/build-electron.js:19-27]():

*   **Extra Metadata**: Injects `ailyBuildFlavor` into the package [.scripts/build-electron.js:21]().
*   **Publish Provider**: Sets provider to `generic` and the URL to the regional updater endpoint [.scripts/build-electron.js:22-23]().
*   **Artifact Naming**: Configures platform-specific naming conventions using `artifactPrefix` [.scripts/build-electron.js:24-26]().
