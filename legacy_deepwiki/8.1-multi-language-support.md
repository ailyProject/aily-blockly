The multi-language support system in Aily Blockly provides internationalization (i18n) capabilities to make the IDE accessible to users worldwide. This system manages localized strings for all user interface components, enabling the application to display text in 11 locales based on user preferences and system settings.

For information about UI themes and visual styling, see [Themes and Styling](#8.2).

## Implementation Architecture

The i18n system is built on the `ngx-translate` library and managed by the `TranslationService` [src/app/services/translation.service.ts:17]().

### Data Flow and Loading Logic

The system uses a lazy-loading approach to minimize the initial bundle size. Translation data is fetched via `HttpClient` only when a language is selected or initialized.

```mermaid
graph TD
    INIT[\"TranslationService.init()\"] --> GET_LIST[\"getLanguageList() from i18n.json\"]
    GET_LIST --> DETECT[\"getSystemLanguage() via navigator.language\"]
    DETECT --> SELECT[\"getSelectedLanguage() from ConfigService\"]
    SELECT --> LOAD[\"setLanguage(lang)\"]
    
    subgraph \"Loading Logic\"
        LOAD --> CHECK{\"Language Loaded?\"}
        CHECK -- No --> FETCH[\"getLanguageData(lang) via HttpClient\"]
        FETCH --> SET_TRANS[\"TranslateService.setTranslation()\"]
        SET_TRANS --> ADD_SET[\"Add to loadedLanguages Set\"]
        CHECK -- Yes --> USE[\"TranslateService.use(lang)\"]
        ADD_SET --> USE
    end
    
    USE --> SAVE[\"ConfigService.save() selectedLanguage\"]
```

Sources: [src/app/services/translation.service.ts:31-49](), [src/app/services/translation.service.ts:61-74](), [src/app/services/translation.service.ts:81-95]()

### Translation Key Schema

Translation files are structured into hierarchical namespaces to maintain order across thousands of strings.

| Namespace | Purpose | Key Examples |
|-----------|---------|--------------|
| `MENU` | Global navigation and action buttons | `MENU.PROJECT_NEW`, `MENU.BUILD`, `MENU.RUN` |
| `BLOCKLY` | Blockly workspace, context menus, and onboarding | `BLOCKLY.WORKSPACE_SELECT_ALL`, `BLOCKLY.ONBOARDING.TOOLBOX_TITLE` |
| `GUIDE` | Onboarding steps and home screen content | `GUIDE.ONBOARDING.STEP1_TITLE`, `GUIDE.TUTORIAL` |
| `BLE_OTA` | Status messages for Bluetooth Over-The-Air updates | `BLE_OTA.CONNECTING_DEVICE`, `BLE_OTA.NEGOTIATING_PACKET_SIZE` |
| `ESP32`/`STM32` | Hardware-specific configuration labels | `ESP32.FLASH_MODE`, `STM32.BOARD` |

## Integration with UI Components

### Angular Components

In the Angular frontend, translations are applied using the `translate` pipe or directive. The `TranslationService` also listens for IPC events from the Electron main process to handle language changes initiated from other windows.

```mermaid
graph LR
    subgraph \"Renderer Process\"
        COMP[\"Angular Component\"]
        TS[\"TranslationService\"]
        PIPE[\"Translate Pipe/Directive\"]
    end
    
    subgraph \"Main Process\"
        IPC[\"ipcMain\"]
    end

    IPC -- \"setting-changed (language-changed)\" --> TS
    TS -- \"setLanguage()\" --> COMP
    COMP -- \"key | translate\" --> PIPE
    PIPE -- \"returns localized string\" --> COMP
```

Sources: [src/app/services/translation.service.ts:44-48](), [src/app/services/translation.service.ts:81-95]()

### Blockly Integration

Blockly-specific translations are stored under the `BLOCKLY` key. This includes custom context menu items like \"AI Explain\" and cross-tab copy/paste operations.

*   **Context Menus:** `BLOCKLY.EXPLAIN_BLOCK` [public/i18n/zh_hk/zh_hk.json:175]()
*   **Workspace Operations:** `BLOCKLY.WORKSPACE_SELECT_ALL` [public/i18n/zh_hk/zh_hk.json:174]()
*   **Onboarding:** The system provides localized walkthroughs for the Toolbox and Workspace [public/i18n/zh_hk/zh_hk.json:176-180]().

### Dynamic Interpolation

The system supports variable interpolation using double curly braces `{{}}` in the JSON files.

*   **Example:** `BLE_OTA.PACKET_SIZE_INFO`: `\"BLE packet size {{packetSize}}B, payload {{payloadSize}}B/packet\"` [public/i18n/en/en.json:117]()
*   **Example:** `NRF5.FLASH_SOFTDEVICE_CONFIRM`: `\"Do you want to flash {{softdevice}} SoftDevice to the device?\"` [public/i18n/en/en.json:97]()

## Localization Utility Functions

The `TranslationService` provides several helper methods for language management:

*   `getSystemLanguage()`: Normalizes browser language codes (e.g., `en-US` to `en_us`) [src/app/services/translation.service.ts:76-79]().
*   `getSelectedLanguage()`: Retrieves the user-persisted language from `ConfigService` or falls back to the system default [src/app/services/translation.service.ts:97-99]().
*   `getLanguageList()`: Dynamically fetches the available locale definitions from `i18n/i18n.json` [src/app/services/translation.service.ts:51-59]().
