## Purpose and Scope

The Electron Main Process serves as the core backend system for the Aily Blockly desktop application, managing application lifecycle, system integrations, and inter-process communication (IPC). It handles privileged operations such as hardware serial communication, local file system access, and native process management that are restricted in the renderer process. This document details the implementation of pooled user data paths, the sub-window pool, and the secure preload bridge.

## User Data Path Pooling and Multi-Instance Support

Aily Blockly implements a custom \"Pooled User Data Path\" system. This allows multiple instances of the app to run simultaneously while isolating Chromium caches (like `GPUCache`) that can cause startup delays if shared or corrupted, while still allowing the reuse of idle instance directories.

### Instance Directory Logic
1. **Scanning**: The app scans `userData/instances/` for directories named `instance-N` [electron/main.js:203-215]().
2. **Locking**: It checks for an `instance.lock` file. If the PID inside is not running, the directory is reused [electron/main.js:220-235]().
3. **Cleanup**: Before use, \"slow caches\" (`GPUCache`, `Code Cache`) are purged to ensure a clean, fast start [electron/main.js:176-188]().
4. **OAuth Routing**: Since multiple instances exist, a shared `oauth-instances.json` file tracks which instance (PID) initiated an OAuth flow to ensure the callback is routed to the correct window [electron/main.js:50-104]().

Sources: [electron/main.js:50-104](), [electron/main.js:176-245]()

## Sub-Window Pool

To eliminate the latency of creating new `BrowserWindow` instances and loading the Angular environment, the main process maintains a background pool of hidden windows.

| Feature | Implementation Detail |
| :--- | :--- |
| **Pool Size** | Maintains 2 pre-warmed windows (`SUB_WINDOW_POOL_SIZE = 2`) [electron/window.js:12](). |
| **Pre-warming** | Windows are created with `show: false` and `opacity: 0`, and they load the base application URL immediately [electron/window.js:82-96](). |
| **Lifecycle** | When a tool or sub-app is opened, a window is \"popped\" from the pool, its opacity is restored, and it is positioned relative to the main window [electron/window.js:131-168](). |
| **Replenishment** | As soon as a window is taken from the pool, a new background window is scheduled for creation [electron/window.js:56-71](). |

Sources: [electron/window.js:11-168]()

## IPC and the Preload Bridge (`electronAPI`)

The `preload.js` script uses `contextBridge.exposeInMainWorld` to provide a safe API surface. It translates complex Node.js objects (like `SerialPort` or `child_process`) into simplified, asynchronous methods for the renderer.

**Key APIs in `electronAPI`:**
- `terminal`: Methods like `init`, `sendInput`, and `onStreamData` for the integrated terminal [electron/preload.js:60-107]().
- `path`: Wraps Node.js `path` and `fs` methods (e.g., `join`, `isExists`, `getUserHome`) [electron/preload.js:18-42]().
- `SerialPort`: Provides `list` and `create` (via `createThrottledSerialPort`) to manage high-frequency hardware data without blocking the UI [electron/preload.js:44-48]().
- `iWindow`: Handles window state (minimize, maximize, focus) and cross-window messaging [electron/preload.js:108-159]().

Sources: [electron/preload.js:12-181](), [src/app/services/electron.service.ts:8-25]()

## Command and Process Management

The `CommandManager` class in `electron/cmd.js` handles the execution of external tools (like `npm` or `aily-builder`).

### Execution Flow
1. **Shell Selection**: Dynamically chooses between `powershell.exe` (Windows), `/bin/zsh` (macOS), or `/bin/bash` (Linux) [electron/cmd.js:157-168]().
2. **Windows Shims**: Automatically appends `.cmd` to `npm` and `npx` commands on Windows to ensure proper execution via `spawn` [electron/cmd.js:171-186]().
3. **Stream Handling**: Captures `stdout` and `stderr`, filtering noisy logs (like `npm http`) and identifying progress patterns (e.g., \"Download progress\") to send back to the UI [electron/cmd.js:102-144]().
4. **Process Cleanup**: Implements `killRegisteredProcessTree` using `taskkill /T /F` on Windows or `SIGTERM` on Unix to ensure child processes (like compilers) don't become zombies [electron/cmd.js:24-70]().

Sources: [electron/cmd.js:24-186](), [src/app/services/cmd.service.ts:53-126]()
