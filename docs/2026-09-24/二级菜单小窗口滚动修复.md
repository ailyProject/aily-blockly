# 二级菜单小窗口滚动修复

## 范围与原因

修复共享 `MenuComponent`，覆盖左上角主菜单与开发板配置使用的二级列表。原逻辑只调整位置，却通过内联样式取消最大高度；菜单内容超过窗口时无法滚到最后一项。

二级菜单允许纵向滚动并显示细滚动条。主菜单和开发板的长二级菜单顶部与一级菜单实际上沿对齐（当前为距窗口顶部 40px），同时不能进入真实 header 区域；底部保留 8px，最大高度同步扣除顶部保留区域。其他共享菜单仍保留上下各 8px。切换分组会重置滚动位置，调整窗口大小会重新定位。测量改在 Angular `afterRender` 中执行，并要求当前菜单已完成视图检查，防止旧行尚未清理时测得错误高度，或无关渲染提前显示旧选项。

顶部保留区域根据后续反馈补充：原先 top=8 时第一项会与 40px 高 header 的原生窗口拖动区重叠，影响鼠标移入和选择。曾设为 header 底部加 8px，最终根据截图反馈改为与一级菜单上沿对齐，不额外偏移。定位与最大高度共用同一个顶部边界。

未修改菜单数据、项目配置、开发板选择或 Coder/Blockly 模式判断。

## 验证

- ChromeHeadless 定向菜单测试：13/13 通过，包含首项避开 header、header 高度变化、长列表末项点击、长短列表切换定位、窗口变化、快速切换旧内容竞争、zone 外事件与关闭清理。
- `node node_modules/typescript/bin/tsc --noEmit -p tsconfig.app.json` 通过。
- `git diff --check` 通过。
- macOS Electron 35 开发客户端，实际主菜单入口使用 40 项临时分区样例，全部 action 为 `noop`；未写入真实分区。用鼠标滚轮滚到底，并实际点击第 40 项，读回选中项为“分区方案 40”。测试后恢复原菜单、窗口尺寸并关闭调试面板。

| 场景 | 实测结果 |
| --- | --- |
| 修复前，窗口高度 600px | 子菜单 top=8、bottom=1216，scrollTop 始终为 0 |
| 第一轮修复，窗口高度 600px | 子菜单 top=8、bottom=592，内容可滚动至第 40 项；后续反馈首项与 header 重叠，已调整 |
| 切换到两项短菜单 | 高度 68px、scrollTop=0、top=74，与父菜单行 top=74 一致 |
| 第一轮菜单打开时窗口调整到 900px | top=8、bottom=892、clientHeight=882，保持可交互 |
| 第二轮 header 避让，窗口高度 773px | headerBottom=40、menuTop=48、firstTop=52、menuBottom=765；实际鼠标选择第 1 项、第 40 项，再滚回第 1 项选择，菜单保持可交互 |
| 最终顶部对齐，窗口高度 773px | primaryTop=40、submenuTop=40、headerBottom=40、bottom=765；实机第一项“分区方案 01”选择成功，菜单保持可交互；13 项测试通过，包含一级菜单 top=72 时同步对齐和末项滚动选择 |

本地截图目录：`/tmp/aily-menu-scroll-qa/`。修复前为 `before.png`；第一轮截图为 `final-top.png`、`final-bottom.png`、`final-selected.png`、`final-short.png`、`final-resize.png`。第二轮 header 避让截图为 `header-top.png`、`header-first-selected.png`、`header-last-selected.png`。最终顶部对齐截图为 `aligned-top.png`，测试日志为 `alignment-tests.log`。临时菜单已恢复，调试面板已关闭，后续验证未调整用户窗口尺寸。

运行环境为 Coder 产品的共享宿主；未另外启动 Blockly 产品或 Windows 打包客户端。控制台既有 Coder 子应用资源/worker 与浏览器能力警告不属于本次菜单变更。
