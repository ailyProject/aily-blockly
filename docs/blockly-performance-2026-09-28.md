## 性能方法

机器为 Apple M4 Pro、24 GiB 内存、macOS 27.0。所有性能变体使用同一 Electron 35.7.5 / Chromium 134；Angular 单元测试另用 Chrome Headless 153，不能混用两者耗时。

使用相同的六类真实 Aily 块定义，构造 **8,285 个块**：41 组重复循环，每组含 100 个延时块和对应数字块，加三个入口块。

- `spread`：41 个分散栈，最大子树 202 块。
- `stack`：全部接入初始化入口，单栈 8,283 块。
- 独立官方 `official`：npm 官方 Blockly 13.3.0 + Thrasos。
- 独立核心 `aily`：当前 Aily Blockly 13.3.0 vendor + Thrasos。
- 独立同渲染器 `aily-ui`：当前 Aily 核心 + 主软件使用的 Aily Thrasos 渲染器和图标。
- `host`：实际生产构建的主软件，经文件打开入口载入临时项目，小地图开启。

每种拓扑/变体各运行三轮，串行启动独立进程。`before` 是合并初步兼容后的主软件、尚未加入本轮性能修复的构建；已有核心与 Worker 小地图优化已包含在基线中。结果取中位数，不把旧项目、不同块形状或分析器开启时的耗时混入对比。

正式采样断言页面内容区域为 1440×800，记录像素比 2 和 Electron GPU 状态。各变体 GPU 合成均启用。最初受 macOS 窗口边界影响、页面高度不同的一轮已移入 `preliminary-viewport/`，不纳入最终数据。

载入指标使用相同 JSON 重载路径，启用相同文本宽度缓存，分别记录同步耗时和两个动画帧后的耗时。主软件另记录从打开项目到工作区/小地图就绪的完整耗时。拖拽使用真实鼠标事件、12 次移动、96×48 工作区位移，验证事件可信和最终坐标。另检查缩放、全量重绘和块 ID/类型/连接/数字字段签名未改变。

性能项目是**渲染与编辑专用夹具**：只在自动生成的私有副本中清空开发板工具链下载声明，以免网络下载污染采样；这不是编译性能测试。原始项目和真实用户配置未用作写入目标。

数据目录：`e2e/.artifacts/blockly-performance-2026-09-28/`。包含每轮 JSON、PNG、环境记录、优化前 renderer/独立页面快照及诊断采样。计时主表由 `scripts/summarize-blockly-performance.cjs` 生成；目录为本地证据，不提交大体积构建文件。

## 三轮正式结果

单位为 ms，均为三轮中位数。同步重绘只统计排队与渲染刷新；包含绘制的值还等待两个动画帧。

| 主软件场景 | 同步重绘：前 → 后 | 含绘制重绘：前 → 后 | 重绘含绘制降幅 | 载入同步：前 → 后 | 实际拖拽：前 → 后 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 分散栈（8,285 块） | 283 → 186 | 1088 → 487 | 55.2% | 2314 → 2378 | 2030 → 2054 |
| 大栈（8,283 后代） | 251 → 127 | 1270 → 465 | 63.4% | 3102 → 3178 | 2500 → 2461 |

**本轮确认的收益是重绘**：同步重绘缩短 34.3% / 49.5%，包含绘制缩短 55.2% / 63.4%。独立 Aily 渲染器的同步重绘也由 311 / 349 ms 降至 220 / 248 ms，支持图标复用是有效路径。

载入同步耗时上升约 2.4%–2.8%，拖拽变化很小；未改动的官方/本地核心对照也存在轮间变化。本轮不声称改善了初次载入或大栈拖拽，更不能声称达到 60 FPS。通知去除同步测量通过了真实 DOM 与持续通知交互测试；下载活动已从正式性能夹具中排除，因此不能从本表单独量化通知修改的收益。

优化后各环境对照：

| 拓扑 | 环境 | 载入同步 | 载入含绘制 | 12 步真实拖拽 | 全量重绘含绘制 |
| --- | --- | ---: | ---: | ---: | ---: |
| 分散 | 官方独立 13 | 1683 | 1847 | 945 | 385 |
| 分散 | Aily 核心独立 13 | 1672 | 1839 | 969 | 374 |
| 分散 | Aily 渲染器独立 13 | 1973 | 2300 | 1579 | 424 |
| 分散 | 主软件 13 | 2378 | 2757 | 2054 | 487 |
| 大栈 | 官方独立 13 | 2051 | 2224 | 1968 | 440 |
| 大栈 | Aily 核心独立 13 | 2051 | 2234 | 1017 | 445 |
| 大栈 | Aily 渲染器独立 13 | 2756 | 3065 | 1820 | 492 |
| 大栈 | 主软件 13 | 3178 | 3532 | 2461 | 465 |

主软件大栈拖拽仍约 2.46 秒；同渲染器独立窗口约 1.82 秒，说明主软件仍有额外开销。官方核心约 1.97 秒，本地核心约 1.02 秒，体现的是本轮之前已有核心补丁的收益。诊断 trace 的主要开销集中在样式重算、布局与绘制；8K Aily 工作区包含约 8.3 万 SVG 后代节点。直接把字体图标改成 SVG 文本的诊断试验没有稳定改善，未纳入产品。

重绘含绘制的主软件三轮范围：

- 分散：优化前 1033–1124 ms；优化后 430–821 ms。
- 大栈：优化前 1204–1279 ms；优化后 464–484 ms。

正式性能断言 **48/48 通过**，所有数据均核验实际版本、视口、GPU、8,285 块、拖拽位移、可信鼠标事件及数据签名。每轮数据及 min/median/max 见数据目录的 `summary.json`。

## 复现

```sh
pnpm perf:blockly:prepare
pnpm perf:blockly:serve
# 浏览 http://127.0.0.1:8313/official.html?topology=stack
# aily.html 和 aily-ui.html 分别是本地核心与相同 Aily 渲染器对照。
# 或另开终端启动独立 Electron 窗口：
pnpm exec electron e2e/performance/electron.cjs

# host 使用 renderer/ 下的实际生产构建；先执行常规 Electron E2E
# global setup，或构建后将 dist/aily-blockly/browser 暂存为 renderer。
BLOCKLY_PERF_ROUNDS=3 BLOCKLY_PERF_LABEL=after pnpm perf:blockly:test
node scripts/summarize-blockly-performance.cjs before after
```

`perf:blockly:prepare` 默认从仓库自带 ESP32-S3 夹具复制并安装固定版本库；可用 `AILY_E2E_PROJECT` 指定已安装库的夹具来源。它只在输出目录生成性能工程。`BLOCKLY_PERF_VARIANTS`、`BLOCKLY_PERF_TOPOLOGIES` 可缩小测试集合。可选 `BLOCKLY_PERF_PROFILE=1` 和 `BLOCKLY_PERF_TRACE=1` 只用于诊断，不能与正常计时混算。
