# project_aug30a 函数视图拖拽优化

环境：macOS arm64、Electron 35.7.5、当前主软件的 `aily-project-blockly 1.0.2`。使用 `/Users/downey/Documents/aily-user-project/project_aug30a` 的隔离副本，保留全部 7765 个积木、320 个变量，只切换显示范围：全局 45 块、`loop()` 715 块。

## 原因与定时器

重复断开已有数字块、放下后继续拖动，复现了停顿。CDP 时间线进一步确认：主窗口的 `.middle-box > router-outlet + *` 通配兄弟选择器，使 Blockly 原生连接调整 SVG 父子关系时，整个画布被标记为样式失效。单次 `UpdateLayoutTree` 涉及 72136 个元素，耗时约 1 秒，连隐藏函数都被重新计算。它不是周期定时器，但出现在松手后的原生连接和渲染阶段，体感同样是一顿一顿。

此外，隐藏函数仍属于完整原生模型；显示较少并没有让后台快照和生成只处理当前函数。定时执行的完整生成和 IPC 也是叠加成本。

| 路径 | 观察与处理 |
| --- | --- |
| 原生 SVG 连接后的样式失效 | 移除主窗口和示例页的通配兄弟选择器。路由激活/重新挂载时给页面宿主添加明确布局类，只在宿主应用原来的尺寸规则；不修改 Blockly SVG、渲染器或主题。 |
| 500ms 代码生成防抖 | 已有逻辑会检查交互，并在异步边界重新检查。保留该逻辑；优化它执行的完整文档复制、宏配置收集和代码行映射。没有减少生成范围或跳过版本校验。 |
| 200ms 代码预览 IPC | 完整映射发送回调约 49–65ms，可能在下一次拖拽期间触发。保留合并发送，交互或独占修改期间仅保存最新待发状态，结束后重试；轻量选择定位继续即时发送。清空项目取消重试。 |
| 小地图分帧和 100ms 待办重试 | 原先只在开始采集时检查交互；开始于空闲的采集可能延续到下一次拖动。每个采集/回退绘制分帧都重新检查，放弃半成品并在交互结束后采集最新场景。重试只在有待办时存在；视口导航继续工作。 |
| 库加载的 50ms 等待 | 仅在加载完成通知后，等待原生事件可用并 `take(1)`，不是编辑器一直运行的整项目轮询。保留。 |
| 编译/上传进度定时器、库的计时器 | 保留原有用途及会话释放逻辑。当前指针采样没有证据把它们认定为本次卡顿主因。 |

## 实现与数据边界

- 完整文档复制改为迭代遍历，不再先 JSON 编码再解析；严格项目复制保留规范化验证，旧 Blockly 状态保留 JSON 的省略、数组空值、日期等语义。公共文档仍与调用方对象隔离，只移除内部重复复制。
- 规范化编码在每次观察中缓存属性名的转义和整数键分类；全部值仍重新读取和验证。缓存不跨快照，直接修改而没有发出 Blockly 事件仍能被版本检查发现。资源 codec 原来的 512 层限制没有放宽。
- 宏配置只检查实际拥有配置的积木，在单次收集中复用父链状态；合并顺序和禁用父级的行为保持一致。
- 代码行映射为已裁剪的源码行建立索引，保留重复行、多行片段、值列范围及原有第一匹配规则。
- 函数视图在结构变化时重建成员和根索引，普通字段和坐标变化复用索引；原生事件被抑制的批量操作仍显式完整刷新。隐藏函数不能成为鼠标吸附目标，程序式连接、撤销和 AI 操作继续使用完整模型。
- 小地图按迭代遍历读取当前原生 SVG；大项目在一次采集中复用祖先平移位置，保留坐标、路径、颜色和禁用状态，继续支持 Worker 与主线程回退。
- 路由布局指令只监听激活和重新挂载，销毁时自动释放订阅，没有新轮询。主窗口、底部可调整面板、Coder、向导和示例列表继续沿用原来的布局尺寸。

## 验证方法与边界

真实 Electron 测试通过鼠标断开原项目已有的数字块，连续拖动三次，共 90 次指针移动，中间松手 650ms；每次均检查原生拖拽生效。记录长任务、动画帧间隔、指针命令耗时、代码生成和定时回调，另存 CDP CPU 采样。结束后撤销全部原生事件组，逐字比较完整序列化、生成代码和完整代码行映射，检查原工程 ABI/ABS 哈希。

最初的 `loop()` 采样混入了自动化 `locator.boundingBox()` 自身的可见性和 SVG 布局查询，每次约 1 秒。最终采样先验证屏幕目标，随后从原生平移坐标得到下一次真实指针位置，避免把测量工具的布局开销当成拖拽开销。原始采样和失败轨迹保留，不能据此宣称整栈或所有 DOM 边界查询已优化。

移除自动化布局查询后，真实样式重算仍有约 1 秒停顿；开启 `invalidationTracking` 后才找到上述通配选择器。给块根额外加渲染器/主题类的诊断实验没有解决问题，未进入实现。最终时间线确认全画布失效已消失，并保留了定时回调和完整项目处理的剩余耗时。

## 实测结果

以下都是完整模型保留 7765 块时的原生输入采样。CDP 时间线在当前 Electron 的软件渲染环境记录；数值用于比较相同工程的路径成本，不代表 FPS 或所有机器的耗时。

| 指标 | 修复前 | 修复后 |
| --- | --- | --- |
| `loop()` 单次最大样式重算 | 1026.8ms，72137 个元素 | 24.2ms，5632 个元素 |
| 全局视图单次最大样式重算 | 先前未单独留存时间线 | 7.6ms，486 个元素 |
| 完整代码生成最大耗时：全局 / `loop()` | 161.2 / 166.0ms | 46.9 / 55.9ms |
| 连续操作期间最大长任务：全局 / `loop()` | 中间修复后的对照为 322 / 1094ms | 339 / 353ms |
| 最终采样最大动画帧间隔：全局 / `loop()` | — | 331.5 / 483.3ms |

约 1 秒的整画布样式失效已消失。松手后完整快照、生成准备及发布仍可形成约 0.3 秒的任务，不能把本次修复解释为所有帧均无停顿。原生指针命令最大耗时为 92 / 95ms，包含自动化和 IPC 调度；代码预览的完整映射回调均发生在手势结束后，未取消原生手势。

应用类型检查、生产渲染层构建及差异检查通过；79 项针对性 ChromeHeadless 检查和 1592 项 ABS 回归通过。11 个不同 Electron 用例全部通过：新生产构建一组保留 7 项通过及 2 项启动定位失败；在同一生产渲染层修正测试的前置条件后，2 项启动用例和 2 项终端/路由布局用例全部通过。启动指针定位必须先等待原生延迟渲染，再以 `blockOnly` 定位；终端测试先关闭隔离新实例的启动登录提示。没有修改产品中的定位、登录或手势语义。

连续拖拽结束后，完整原生撤销恢复了逐字相同的序列化、源码和代码行映射。保存重开验证 7765 块、320 个变量保留。原工程 ABI/ABS SHA-256 分别仍为 `bf63caeca0330b09c7995038b3e152f782064ccc131c7db8c8858ed7eba1455c` 和 `93645b4f66dddcf5245d3dd17d6da88cbda29bad962623cb27a6bdcac53c91b3`。

当前 `http://localhost:4200/` 开发服务的主窗口模块已提供明确布局类，旧通配选择器消失；没有重启开发进程。最终补看已有窗口时 Mac 锁屏，未继续操作用户窗口。验收依据是上述独立 Electron 的真实输入及持久化检查。
