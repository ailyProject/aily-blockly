This document describes the Angular renderer process that serves as the main user interface for the Aily Blockly IDE. The Angular frontend provides the visual programming environment, tool panels, and project management interface. For information about the Electron main process and IPC communication, see [Electron Main Process](#2.1).

## Application Bootstrap Process

The Angular application initializes through a standard bootstrap sequence that sets up core services and the component hierarchy. The application entry point is defined in `main.ts` and loads the root `AppComponent`.

```mermaid
graph TD
    [\"main.ts\"] --> [\"bootstrapApplication\"]
    [\"bootstrapApplication\"] --> [\"appConfig\"]
    [\"bootstrapApplication\"] --> [\"AppComponent\"]

    [\"appConfig\"] --> [\"Application Providers\"]
    [\"Application Providers\"] --> [\"Router with Hash Location\"]
    [\"Application Providers\"] --> [\"HttpClient\"]
    [\"Application Providers\"] --> [\"TranslateService\"]

    [\"AppComponent\"] --> [\"ElectronService.init()\"]
    [\"AppComponent\"] --> [\"ConfigService.init()\"]
    [\"AppComponent\"] --> [\"AuthService.initializeAuth()\"]
    [\"AppComponent\"] --> [\"TranslationService.init()\"]
    [\"AppComponent\"] --> [\"ToolI18nService.loadChildTools()\"]
```

The `AppComponent` serves as the application shell and coordinates the initialization of essential services in a specific sequence during `ngOnInit()`:

- `ElectronService.init()`: Establishes IPC communication with the main process [src/app/app.component.ts:41]().
- `ConfigService.init()`: Loads application configuration and settings [src/app/app.component.ts:42]().
- `AuthService.initializeAuth()`: Restores user session and JWT [src/app/app.component.ts:48]().
- `TranslationService.init()`: Initializes internationalization support [src/app/app.component.ts:44]().
- `ToolI18nService.loadChildTools()`: Preloads translations for external tool modules [src/app/app.component.ts:45]().

## Routing and Navigation

The application uses a hash-based routing strategy (`withHashLocation()`), which is required for Electron's file-based protocol. The routing structure is divided into the main IDE window and standalone tool windows.

| Path                   | Component                | Purpose                                                                           |
| ---------------------- | ------------------------ | --------------------------------------------------------------------------------- |
| `/main`                | `MainWindowComponent`    | The primary IDE shell with layout panels [src/app/app.routes.ts:10-11]().         |
| `/main/guide`          | `GuideComponent`         | Welcome and getting started page [src/app/app.routes.ts:19-20]().                 |
| `/main/blockly-editor` | `BlocklyEditorComponent` | The visual programming workspace [src/app/app.routes.ts:46-47]().                 |
| `/child-tool/:toolId`  | `ChildToolHostComponent` | Wrapper for external tools (e.g., MQTT debugger) [src/app/app.routes.ts:95-96](). |
| `/serial-monitor`      | `SerialMonitorComponent` | Standalone serial communication tool [src/app/app.routes.ts:76-77]().             |

Sources: [src/app/app.routes.ts:1-184](), [src/app/app.config.ts:12]()

## Main Window Layout

The `MainWindowComponent` implements a three-pane architecture using `ng-zorro-antd` layout components. It manages the visibility and resizing of the side and bottom panels.

```mermaid
graph TD
    [\"MainWindowComponent\"] --> [\"HeaderComponent\"]
    [\"MainWindowComponent\"] --> [\"NzLayout\"]
    [\"NzLayout\"] --> [\"NzContent\"]
    [\"NzLayout\"] --> [\"NzSider (Right Panel)\"]
    [\"NzContent\"] --> [\"RouterOutlet (Editor)\"]
    [\"NzContent\"] --> [\"Bottom Panel (Resizable)\"]
    [\"Bottom Panel\"] --> [\"LogComponent\"]
    [\"Bottom Panel\"] --> [\"TerminalComponent\"]
    [\"MainWindowComponent\"] --> [\"FooterComponent\"]
```

### Resizable Panels

The layout supports dynamic resizing through `nz-resizable`:

- **Bottom Panel**: Controlled by `showBbox`. It contains a tabset for \"Log\" and \"Terminal\" [src/app/main-window/main-window.component.html:11-59]().
- **Right Sider**: Controlled by `showRbox`. It hosts various tools like `aily-chat`, `code-viewer`, or `serial-monitor` [src/app/main-window/main-window.component.html:61-107]().

### UI State Management

The `UiService` acts as the central coordinator for layout changes. It uses an `actionSubject` to broadcast panel toggle events [src/app/services/ui.service.ts:20](). The `MainWindowComponent` subscribes to these actions in `ngAfterViewInit()` to update local visibility flags like `showRbox` and `showBbox` [src/app/main-window/main-window.component.ts:152-193]().

Sources: [src/app/main-window/main-window.component.ts:68-193](), [src/app/main-window/main-window.component.html:1-111](), [src/app/services/ui.service.ts:18-169]()

## Component Architecture

### Log Panel (`LogComponent`)

The Log panel provides high-performance visualization of system and project logs.

- **Virtualization**: Uses `@tanstack/angular-virtual` to handle thousands of log entries without UI lag [src/app/tools/log/log.component.ts:48-53]().
- **ANSI Parsing**: Employs an `AnsiPipe` and `fancy-ansi` to render colored terminal output in the HTML view [src/app/tools/log/log.component.ts:6-13]().
- **Interactivity**: Supports single-click to copy and double-click to send log context to the AI Chat [src/app/tools/log/log.component.ts:210-228]().

### Terminal (`TerminalComponent`)

The integrated terminal provides a command-line interface to the underlying OS or hardware toolchains.

- **Xterm.js**: Uses `Terminal` from `@xterm/xterm` for the terminal emulator [src/app/tools/terminal/terminal.component.ts:2]().
- **Theming**: Dynamically reads CSS variables (e.g., `--aily-editor-bg`) to match the application's dark theme [src/app/tools/terminal/terminal.component.ts:89-115]().
- **Communication**: Interfaces with `TerminalService`, which pipes data through Electron IPC to a `node-pty` process in the main process [src/app/tools/terminal/terminal.component.ts:72-78]().

### Onboarding System

The `OnboardingComponent` provides an overlay for guiding new users through the IDE features.

- **Service-Driven**: Managed by `OnboardingService`, which controls visibility (`show$`) and step configuration (`config$`) [src/app/main-window/main-window.component.ts:129-136]().
- **Integration**: The component is rendered as a top-level overlay in the `MainWindowComponent` [src/app/main-window/main-window.component.html:114-118]().

Sources: [src/app/tools/log/log.component.ts:18-74](), [src/app/tools/terminal/terminal.component.ts:18-86](), [src/app/main-window/main-window.component.ts:129-136]()

## Styling and Themes

The IDE is styled using SCSS with a focus on a \"Pro\" dark aesthetic.

- **Global Styles**: Defined in `styles.scss`, setting the base background `var(--aily-bg-primary)` and MiSans font [src/styles.scss:1-16]().
- **Blockly Customization**: Extensive CSS overrides for Blockly elements like `blocklyDropDownDiv` and `blocklyMenuItem` to align them with the Ant Design (ng-zorro) style [src/styles.scss:182-254]().
- **Utilities**: Provides common utility classes like `.ccenter` for flex centering and `.sscroll` for thin scrollbars [src/styles.scss:44-123]().

Sources: [src/styles.scss:1-272](), [src/app/main-window/main-window.component.scss:1-218]()
