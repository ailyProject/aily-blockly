The compilation process in Aily Blockly transforms visual Blockly programs into executable firmware. This process is managed by a multi-stage pipeline involving code generation, dependency resolution, pre-processing, and execution of the `aily-builder` toolchain (an optimized wrapper around the Arduino CLI).

## Overview

Compilation is orchestrated by the `BuilderService`, which manages the lifecycle of a build from initial code generation to final binary output. The system utilizes a background preprocessor to minimize build times and a streaming terminal interface for real-time feedback.

## Preprocessing Pipeline

The preprocessing stage, handled by `preprocess.js`, is a critical background task that prepares the build environment and resolves dependencies. It is triggered automatically when workspace dependencies change.

### Dependency Mapping

The preprocessor scans the project's `package.json` and the selected board's `board.json` to map:

1.  **Compilers**: Packages prefixed with `@aily-project/compiler-`. [child/scripts/preprocess.js:166-168]()
2.  **SDKs**: Packages prefixed with `@aily-project/sdk-`. [child/scripts/preprocess.js:169-170]()
3.  **Libraries**: Packages prefixed with `@aily-project/lib-`. [child/scripts/preprocess.js:119-123]()

### Parallel Library Processing

Libraries are processed in parallel using `processLibrariesParallel`. The system maintains a `library-cache.json` to avoid redundant extractions. [child/scripts/preprocess.js:125-133]()

### Preprocess Trigger Logic

The `_BuilderService` manages a `dependencySubject` that debounces change events. It implements mutual exclusion to ensure preprocessing doesn't interfere with active builds or AI operations. [src/app/editors/blockly-editor/services/builder.service.ts:141-169]()

| Mutex Condition         | Behavior                                                                                                                      |
| :---------------------- | :---------------------------------------------------------------------------------------------------------------------------- |
| **AI Waiting**          | Marks `pendingPrecompile = true` and defers execution. [src/app/editors/blockly-editor/services/builder.service.ts:151-155]() |
| **NPM Installing**      | Defers preprocessing until installation completes. [src/app/editors/blockly-editor/services/builder.service.ts:158-162]()     |
| **Active Build/Upload** | Skips preprocessing to avoid file locking conflicts. [src/app/editors/blockly-editor/services/builder.service.ts:165-169]()   |

## Compilation Execution (`compile.js`)

When a user initiates a build, the system executes `compile.js`. This script reads the configuration generated by the preprocessor and invokes the `aily-builder` toolchain.

### Build Artifacts

The compiler generates a temporary Arduino sketch structure in the project's `.temp` directory:

- **Sketch File**: `.temp/sketch/sketch.ino` [child/scripts/compile.js:66-72]()
- **Preprocess Cache**: `.temp/preprocess.json` [child/scripts/compile.js:67-77]()

### Toolchain Invocation

The script spawns a node process targeting `aily-builder/index.js` with specific flags:

- `--board`: The target board identifier (e.g., `esp32:esp32:esp32s3`). [child/scripts/compile.js:115]()
- `--preprocess-result`: Path to the JSON containing resolved library and tool paths. [child/scripts/compile.js:116]()

## Progress Monitoring and Cache Management

### Flash/RAM Usage

After a successful build, the `aily-builder` output is parsed to extract hardware resource usage. This is reported back to the `BuilderService` and displayed in the UI.

### Cache Management

To ensure build reproducibility, the system provides mechanisms to clear caches:

1.  **Automatic Reset**: Triggered on board change via `compile-reset`. [src/app/services/builder.service.ts:30-34]()
2.  **Manual Purge**: The `clearCache` function removes the `.temp` directory and the platform-specific build cache path. [src/app/services/builder.service.ts:116-138]()

### Terminal Streaming

Compilation output is streamed through `TerminalService` using `node-pty`. This allows the IDE to display real-time logs in the diagnostic panel while parsing for specific error patterns or progress percentages. [electron/terminal.js:175-185](), [src/app/tools/terminal/terminal.service.ts:74-147]()
